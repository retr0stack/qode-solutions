# Контент

Весь текст сайта живёт здесь. В компонентах нет ни одной строки — это нужно
и для правок без разработчика, и для будущей мультиязычности.

Типы лежат в [`types.ts`](./types.ts). Если TypeScript ругается после
правки — скорее всего, вы забыли обязательное поле; посмотрите тип.
Проверить всё сразу: `npm run typecheck`.

## Файлы

| Файл | Что внутри |
| --- | --- |
| `site.ts` | Название, дескриптор, домен, телефон, почта, WhatsApp, Telegram, города, соцсети |
| `nav.ts` | Верхнее меню и футер |
| `home.ts` | Тексты hero, карточки направлений, блок отличий, шапки секций главной |
| `services.ts` | Пять направлений и их подпункты |
| `process.ts` | Пять шагов «Как мы работаем» |
| `stack.ts` | Сетка технологий |
| `faq.ts` | Вопросы и ответы |
| `team.ts` | Основатели |
| `cases.ts` | Кейсы (пока пусто) |
| `forms.ts` | Подписи полей, вилки бюджета, сообщения валидации, состояния формы |
| `seo.ts` | Заголовки и описания страниц |

Импортировать удобно из корня пакета:

```ts
import { hero, services, contacts } from "@/content";
```

## Добавить услугу

Открыть `services.ts` и дописать объект в `items` нужного раздела:

```ts
{
  title: "Аудит скорости сайта",
  description: "Смотрим Core Web Vitals, находим узкие места, отдаём план работ.",
}
```

`title` — короткий, без «мы предлагаем». `description` — одно-два
предложения по делу.

**Новый раздел** (шестое направление) — объект в массив `services`:

```ts
{
  slug: "analytics",              // только латиница и дефисы: это id якоря
  section: "Аналитика",           // заголовок раздела
  summary: "Счётчики, события, отчёты",  // одна строка для боковой навигации
  items: [ /* … */ ],
}
```

Дальше ничего править не нужно: sticky-навигация на `/services`, якоря
в футере, роут `/services/[slug]` и `sitemap.xml` собираются из этого
массива автоматически.

## Добавить члена команды

Дописать объект в массив `team` в `team.ts`:

```ts
{
  slug: "designer",               // латиница, уникальный
  name: "Имя Фамилия",
  role: "Дизайнер",
  bio: [
    "Первая строка о специализации.",
    "Вторая — о бэкграунде.",
  ],                              // 2–3 строки, каждая = отдельный абзац
  photo: { src: "/team/designer.webp", alt: "Дизайнер QODE SOLUTIONS" },
  links: [
    { label: "Telegram", href: "https://t.me/username", external: true },
  ],
}
```

Фото: **800×1000** (вертикальное, 4:5), WebP, в `/public/team/`. Лицо
в верхней половине кадра — карточка кадрирует снизу. `alt` описывает
человека, а не «фото».

Пока `photo.src` пустая строка, на месте портрета показывается фирменная
заглушка со знаком — не битая картинка и не серый прямоугольник. Появится
путь к файлу — заглушка уйдёт сама.

Сетка перестроится сама. Чтобы показать в конце плашку вакансии —
`teamOpenRole.enabled = true` в том же файле.

## Добавить кейс

Портфолио пока пустое, но всё готово: тип `CaseStudy`, карточка
`components/cases/CaseCard.tsx` и роут `/cases`. Достаточно дописать
объект в массив `cases` в `cases.ts` — в `cases.ts` есть готовый
закомментированный пример.

```ts
{
  slug: "example-shop",
  client: "Название клиента",     // согласуйте упоминание с клиентом
  title: "Что сделали",
  summary: "Одно-два предложения: что было и что стало.",
  year: 2026,
  tags: ["Сайты", "Интеграции"],  // берите из названий разделов services.ts
  cover: { src: "/cases/example-shop.webp", alt: "Главная страница магазина" },
  result: "Обработка заказа — с 15 минут до 2",  // необязательно, но сильно
}
```

Обложка: **1600×1200** (4:3), WebP, в `/public/cases/`.

Как только в массиве появится первый кейс, `hasCases` станет `true`,
и `/cases` попадёт в `sitemap.xml`. Ссылку в меню нужно добавить руками
в `nav.ts` — чтобы вы сами решили, когда раздел готов к показу.

## Правила текста

- Без маркетингового шума: «делаем сайты», а не «создаём digital-опыт».
- Цифры и сроки конкретные. Если точных нет — вилка.
- Заголовки короткие: дисплейные размеры рассчитаны на 3–5 слов
  в строке, длинный заголовок сломает композицию.
- Знак `₸` для тенге, неразрывный пробел перед ним не нужен.
- Тире — длинное (`—`), кавычки — «ёлочки».

## Мультиязычность

Сейчас всё на русском, `kk` и `en` заложены структурно. Порядок
подключения, когда дойдёт до дела:

1. Переименовать файлы в `services.ru.ts` и рядом положить
   `services.kk.ts`, `services.en.ts` с той же структурой.
2. В `index.ts` сделать резолвер `getContent(locale)` — сигнатуры
   экспортов не меняются, поэтому страницы править не придётся.
3. Включить `[locale]`-сегмент в роутинге и `alternates.languages`
   в метаданных.

Тип `Locale` и список `locales` уже есть в `types.ts` и `site.ts`.
Шрифты казахские глифы (ә, ғ, қ, ң, ө, ү, һ) уже покрывают — субсеты
`cyrillic-ext` подключены и грузятся только там, где эти буквы есть.
